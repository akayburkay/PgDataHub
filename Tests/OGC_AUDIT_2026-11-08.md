# OGC/CQL2 doğrulama ve performans raporu — 2026-11-08

## Uygunluk beyanı ve kapsam

`/conformance` şu anda yalnız OGC API Features Part 1 `core`, `geojson` ve `oas30` sınıflarını ilan eder. Yerel otomatik testler landing page, discovery, GeoJSON items, paging, BBOX, datetime, CRS yanıtları, queryables ve dinamik OpenAPI için geçmiştir. Bu testler resmî CITE sertifikasyonu değildir. Part 2 CRS, Part 3 Filtering ve CQL2 uygunluk sınıfları ilan edilmez. CQL2 implementasyonu, standardın yalnız belgelenmiş bir alt kümesini karşılar; özellikle tüm temporal interval ilişkileri, aritmetik `div`/`^`, tüm spatial literal biçimleri, array ve özelleştirilmiş fonksiyon sınıfları eksiktir.

Resmî OGC API Features ETS/TEAM Engine çalıştırılamadı: mevcut Java 11, güncel TEAM Engine'in istediği Java 17'den eski; Docker Desktop Linux daemon pipe'ı bulunmuyor. Test API'si yalnız in-process `TestServer` üzerinden erişilebilir; TEAM Engine'in ulaşacağı sabit ağ URL'si yok. Bu nedenle resmî ETS sonucu: çalıştırılamadı, başarı/başarısızlık sayısı 0. Alternatif olarak gerçek PostgreSQL/PostGIS ile xUnit HTTP/SQL testleri çalıştırıldı.

## Hata düzeltmeleri

- CQL2-JSON `isNull` operatörü Text `IS NULL` ile aynı SQL'i üretir.
- Geçersiz JSON BBOX koordinatları `400` döner.
- Geçersiz WKT ve GeoJSON koordinatları veritabanına gönderilmeden reddedilir; endpoint `400` döner.
- Negatif koordinatlı Text BBOX/WKT doğru ayrıştırılır.
- `filter-crs` için bilinmeyen SRID, gerçek PostGIS endpoint'inde `400` olarak doğrulandı.

`pgdatahub.ini` değiştirilmedi. Kodda `/conformance` sınıfları artırılmadı.

## Ölçüm yöntemi

Windows NT 10.0.26200, .NET 10.0.9, 16 mantıksal CPU, yaklaşık 16 GiB kullanılabilir RAM. PostgreSQL sürümü bu raporda kaydedilmedi. Her büyüklükte 10 bin, 100 bin ve 1 milyon nokta `generate_series` ile tek oturumluk `TEMP TABLE` içinde oluşturuldu; PK, kategori B-tree ve geometri GiST indeksleri, ardından `ANALYZE` kullanıldı. Her senaryo 1 warm-up ve 3×10 ölçüm içerir. Aşağıdaki sayılar SQL oluşturma + Npgsql komutu + sonuç okuma süresidir; HTTP ölçümü değildir. RPS sütunu tek seri isteğin ortalama gecikmesinin tersidir, eşzamanlı sunucu kapasitesi değildir.

Legacy, CQL2 Text ve CQL2 JSON sonuç dizileri her büyüklükte eşit çıktı. BBOX ve eşdeğer `S_INTERSECTS` sonuçları da eşit çıktı. Sayfalı sorgularda `EXPLAIN (ANALYZE, BUFFERS)` PK index scan seçti; seçici sayfasız spatial count sorgusunda `cql_bench_geom` GiST Bitmap Index Scan seçildi (1m satırda yaklaşık 1.92 ms, 2500 eşleşme). Bu plan farkı `ORDER BY id LIMIT 100` nedeniyle beklenebilir. CQL için belirgin bir darboğaz kanıtlanmadığı için spekülatif optimizasyon yapılmadı.

In-process HTTP `TestServer` üzerinde, küçük üç satırlı fixture ile eşzamanlı 10/50/100 istek sırasıyla 42/171/814 RPS, P95 229/278/94 ms ve sıfır hata verdi. Bu sonuçlar bağımsız ağ yük testi veya büyük veri eşzamanlılık kapasitesi olarak yorumlanmamalı. CPU ve RAM *tüketimi* ölçülmedi; yalnız ortam kapasitesi kaydedildi. 5m+ veri ve resmî CITE koşusu gerçekleştirilmedi.
